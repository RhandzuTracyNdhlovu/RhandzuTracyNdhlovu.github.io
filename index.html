Case Studies
01 SSH Configuration
The problem

I wanted to allow SSH connections to my PC, but only on networks I trust — Private and Domain, not Public. I set up the firewall rule, then tried to connect to test it.

What I did

I ran ssh localhost in CMD. It said "connection refused." I ran sc query sshd and found OpenSSH Server wasn't installed. The Settings app and the ms-settings:optionalfeatures shortcut both failed to show the option. I opened PowerShell as admin and ran Add-WindowsCapability -Online -Name OpenSSH.Server. It installed. I started the service, set it to start automatically, then ran ssh localhost again.

connection refused
firewall rule — Private/Domain only
install (typo, then fixed)
port 22 listening
VERIFIED
What it proved

This time it worked. I got a fingerprint prompt, typed "yes," entered my password, and landed at my own shell prompt. Running echo %SSH_CONNECTION% from inside that session showed a real remote port talking to port 22 — proof it was an actual SSH connection, not just a local command window.

SSH_CONNECTION confirmed
02 Controlled Folder Access
The problem

My Documents, Photos, Videos, and Project folders held my most important data. If ransomware got in, I could lose all of it. I decided to test whether Controlled Folder Access could actually stop that.

What I did

I turned on CFA for those folders. While checking settings, I found "block potentially unwanted apps" was off — I turned it on and confirmed it in Windows Security. I downloaded a test app; it was blocked. I ran a command to write directly into my Documents folder; it was denied, with the message "Protected folder access blocked." I added Command Prompt as an allowed app and ran the same test again — it worked.

CFA turned on
write denied
protection history entry
cmd.exe allowed
VERIFIED
What it proved

I knew it worked because when I tried to write into Documents from CMD, access was denied. A setting that's switched on doesn't prove anything by itself. My own test did — and after allowing cmd.exe, I confirmed the write actually landed by reading the file back with type, not just checking for an error message.

write confirmed with type
03 Windows Defender Real-Time Protection (EICAR)
The problem

I wanted to know if Windows Defender's real-time protection actually worked, not just turned on. EICAR is a safe test file built for exactly this — it's not real malware, but antivirus tools are built to catch it.

What I did

I went to a website with the EICAR test string and tried to download it. That didn't work directly, so I used Ctrl+S to save it as eicar.com in Downloads, with "all files" selected. The moment I hit save, a Windows Defender notification popped up in the corner.

EICAR test string
saving as eicar.com
threat notification
VERIFIED
What it proved

I checked Protection History and found an entry about a threat being caught. Then I checked Downloads — the file was not there. Real-time protection had caught it and removed it, not just flagged it and left it alone.

threat blocked — severe
04 User Account Control (UAC)
The problem

I wanted to know if UAC actually stopped programs from making admin-level changes without my permission — not just turned on. If it wasn't working properly, any program could make important changes to my PC without me knowing.

What I did

I opened CMD normally and ran net session — "access denied." I opened CMD as administrator, got a UAC prompt, allowed it, and ran net session again — it worked. Then I lowered UAC to "Never Notify" and repeated the test. CMD normally still gave "access denied." But CMD as administrator opened with no prompt at all, and net session still worked.

UAC — default level
normal CMD — denied
admin CMD — works
UAC — never notify
admin CMD — still works, no prompt
VERIFIED
What it proved

The command succeeded either way. What changed was the notification. On default, UAC warns me before a program gets admin access. On "Never Notify," a program can get that access with nothing showing on my screen at all. UAC prompts run on Windows' isolated secure desktop, so the prompt itself can't be captured by a standard screenshot tool — the before/after command results are what I used to prove the behavior instead.

05 Windows Update
The problem

I was trying to verify that Windows Update was actually maintaining the security of my system — not just that the setting was turned on. Missing or delayed security updates leave known vulnerabilities unpatched, and that gives attackers an opportunity to get in.

What I did

I opened Settings, went to Windows Update, and checked update history — all updates showed successful. I checked for pending updates and caught one in progress: a Security Intelligence Update for Microsoft Defender Antivirus, KB2267602, downloading. I checked update history again afterward.

history — before
KB2267602 — downloading
VERIFIED
What it proved

It showed successful and installed. You can not just say the system is up to date because Windows Security is on — you need to check more often.
